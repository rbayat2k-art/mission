# رفع مانع ثبت UI در تست Android — ۲۰۲۶-۰۹-۱۲

## شواهد و محدوده

انتشار وب `2.10.2` برای اختیاری‌بودن توضیح نتیجه در Commit `62f9913c7f504b92a3f2031d7d7a883477f707f3` روی main ثبت شده است. گردش‌کار وب main با شماره `34680607625` موفق بود، ولی گردش‌کار Android شماره `34680607631` در هر دو تلاش، روی API 35 پس از پیام موفق نوشتن XML از `uiautomator dump` با کد `137` خارج شد. ساخت APK آزمایشی و آزمون‌های API 23 و 29 موفق بودند. انتشار Production متوقف ماند؛ این سند ادعای Deploy نیست.

محل شکست قطعی، دستور ابزار ثبت UI است. علت پایین‌دستی کشته‌شدن فرایند ابزار (برای مثال حافظه یا چرخه عمر ابزار) از این لاگ‌ها ثابت نشده و نباید به‌عنوان OOM یا کرش قطعی برنامه گزارش شود. صرف پیام موفق ابزار نیز برای قبول آزمون کافی نیست.

## تصمیم محدود

- فقط helper ثبت UI و تست‌های آن از شاخه محلی Android به‌صورت انتخابی استفاده شدند؛ تغییرات APK، امضا، انتشار و گردش‌کار کامل آن شاخه وارد این انتشار نشدند.
- هر بار یک مسیر UUID جدید در شبیه‌ساز و یک فایل موقت تازه روی runner استفاده می‌شود. خروجی قبلی هرگز شاهد موفقیت نیست.
- فقط status صفر یا `137`، همراه پیام تکمیل دقیق همان مسیر، pull موفق و XML کامل با ریشه hierarchy و node واقعی متعلق به بسته TAPRA قابل بررسی است.
- در حالت `137` هشدار صریح ثبت می‌شود؛ ادعا نمی‌شود خود دستور موفق خارج شده است. همه کدهای دیگر، Timeout، خروجی ناقص و فایل متعلق به برنامه دیگر شکست قطعی‌اند.
- wrapper جدید قبل و بعد از ثبت UI، فرایند اصلی برنامه و فعالیت واقعاً foreground کاربر صفر را بررسی می‌کند؛ وجود رکورد قدیمی MainActivity کافی نیست. شناسه فرایند باید ثابت بماند تا بسته‌شدن و راه‌اندازی دوباره برنامه حتی بدون لاگ کرش نیز رد شود. سپس نبود شواهد کرش Java/native و ANR بررسی می‌شود.
- پیام الزامی باتری، رد صفحه خطا/Loading و کنترل‌های قبلی گردش‌کار حفظ شدند. باقی‌ماندن روی صفحه باتری پس از whitelist نیز شکست است.
- retry خودکار، راه‌اندازی مجدد برنامه برای پنهان‌کردن شکست، پاک‌کردن logcat یا نادیده‌گرفتن نتیجه ابزار وجود ندارد.
- فایل XML و لاگ شبیه‌ساز محلی و بدون ورود کاربر واقعی، حداکثر ۱۴ روز به‌عنوان artifact تست نگهداری می‌شوند. Production، فایل کاربران و اسرار امضا به این گردش‌کار راه ندارند.

## تست‌ها

۱۳ تست capture و ۱۰ تست wrapper (جمعاً ۲۳) شامل خروجی صفر/۱۳۷، فایل تازه/قدیمی/خراب/ناقص، pull و Timeout، هشدار صریح، تداخل foreground با رکورد قدیمی، فرایند مرده یا دوباره راه‌اندازی‌شده، از دست‌رفتن foreground، کرش Java/native و ANR پس از capture، صفحه باتری/خطا، فرمت Android قدیم و جدید، خطای فرمان و خروجی CLI بدون داده برنامه هستند. تست wrapper سیاست واقعی capture را با ADB مصنوعی و فایل واقعی موقت اجرا می‌کند.

تست‌های قرارداد گردش‌کار نیز اجرای wrapper و تمام کنترل‌های قبلی را الزام می‌کنند. انتظار قدیمی مبنی بر وجود مستقیم عبارت `uiautomator dump` در YAML، به بررسی فراخوانی wrapper و دستور واقعی داخل helper تغییر کرد؛ تست ثبت UI حذف نشد.

TypeScript و Lint محلی موفق‌اند. کل Unit، Build دقیق lockfile، E2E، Audit و اجرای شبیه‌سازهای API 23/29/35 روی Commit جدید باید قبل از انتقال به main و Deploy موفق باشند. نتیجه CI و انتشار در گزارش تحویل ثبت خواهد شد.

## محدودیت‌ها و بازگشت

این آزمون smoke است، نه اثبات تمام عملکردهای GPS پس‌زمینه یا گوشی فیزیکی. کنترل صفحه از نوع package/foreground و متن خطا است و به‌تنهایی صحت تصویری تمام اجزای WebView را اثبات نمی‌کند؛ آزمون‌های مرورگر جداگانه همچنان لازم‌اند.

هیچ فایل بومی Android، وابستگی، schema یا deploy.sh تغییر نکرده است. نیاز به APK جدید برای تغییر اختیاری‌بودن توضیح وجود ندارد. بازگشت از این اصلاح تست با revert تغییرات محدود ابزار ممکن است؛ بازگشت انتشار وب تابع دستورالعمل رسمی Deploy و نسخه پشتیبان قبل از migration است. نسخه فعلی Production هنگام تدوین این سند `2.10.1` روی `4fc1bb07b2723bf8f2c478b9c501eec849818520` بوده است.
