# ADR-003: توضیح اختیاری نتیجه کارمند

## وضعیت

درخواست کاربر پذیرفته‌شده؛ پیاده‌سازی محلی، هنوز منتشر نشده است.

## تاریخ

۲۰۲۶-۰۹-۱۲

## مسئله

کارمند باید بتواند نتیجه کار را بدون نوشتن توضیح ثبت کند. اجبار فرم و سرور، حتی برای نتیجه‌های مشخصی مانند «تعطیل بود»، مانع ادامه کار می‌شد. تغییر صرفاً ظاهری کافی نیست؛ فرم و اعتبارسنجی API باید یک قرارداد داشته باشند.

## تصمیم

- توضیح نتیجه در مأموریت تک‌مرحله‌ای، مرحله مأموریت چندمرحله‌ای و هر تسک اختیاری است؛ شامل نتیجه ناموفق، «سایر» و ارجاع صریح به سرپرست.
- انتخاب نتیجه همچنان لازم است. قواعد GPS، فعالیت فعال، مقصد، دسترسی، تکمیل همه تسک‌ها، هزینه و امتیاز تغییر نمی‌کنند.
- در API تکمیل مأموریت و اعتبارسنجی نتیجه تسک، توضیح ارسال‌نشده، `null`، خالی یا فقط فاصله به رشته خالی تبدیل می‌شود. متن یک‌حرفی پذیرفته و متن نوشته‌شده trim می‌شود. سقف قبلی ۴۰۰۰ کاراکتر برای توضیح تسک حفظ می‌شود. مقدار غیرمتنی با ۴۰۰ رد می‌شود.
- انتخاب یا عوض‌کردن نتیجه نباید متن ساختگی به نام کارمند درج کند یا توضیح نوشته‌شده او را جایگزین کند. خلاصه ساختاریافته نتایج تسک‌ها در مرور نهایی همچنان باقی است.
- ارجاع به سرپرست فقط با انتخاب صریح کارمند ایجاد می‌شود. بدون توضیح نیز درخواست و اعلان قبلی برقرار است، اما پیام متنی خالی در گفت‌وگو ساخته نمی‌شود. نمایش «بدون توضیح» فقط متن رابط است، نه گزارش ساختگی ذخیره‌شده.
- این تصمیم فقط بند اجبار توضیح در ADR-001 را جایگزین می‌کند. الزام متن برای ارسال یک پیام مستقل در گفت‌وگو یا فرم مستقل درخواست پیگیری تغییر نمی‌کند.

## پیامدها

- مدیر ممکن است فقط نتیجه ساختاریافته را ببیند و توضیح اضافه‌ای دریافت نکند؛ این پیامد انتخاب اختیاری‌بودن متن است.
- داده‌های قبلی بازنویسی نمی‌شوند و migration لازم نیست. این تغییر در وب و API است، نه کد بومی Android.
- نسخه قدیمی رابط ممکن است تا دریافت نسخه جدید همچنان توضیح بخواهد؛ انتشار وب/سرور اقدام جداگانه است.

## معیار پذیرش

- ادامه و ثبت نتیجه بدون توضیح برای همه گزینه‌ها ممکن باشد؛ بدون انتخاب نتیجه ممکن نباشد.
- متن اختیاری با تغییر نتیجه و رفت‌وبرگشت مراحل محفوظ بماند.
- ارجاع بدون توضیح نه حذف شود و نه پیام خالی ایجاد کند.
- بدون GPS، مقصد یا تعیین وضعیت همه تسک‌ها، قواعد قبلی همچنان مانع تکمیل شوند.
- تست مسیر واقعی API با پایگاه داده آزمایشیِ شبیه‌سازی‌شده و تست رابط دسکتاپ/نمای موبایل انجام شود؛ این تست‌ها جایگزین آزمون روی گوشی واقعی یا MySQL واقعی نیستند.
