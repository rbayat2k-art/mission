# تصمیم CI: دیتابیس واقعی و Android Debug آزمایشی

CI باید دیتابیس Production را شبیه‌سازی کند، بدون استفاده از داده یا رمز واقعی.
MariaDB 10.11 خط اصلی سازگاری است، چون Production روی همین خانواده اجرا می‌شود؛
MySQL 8.4 نیز به‌عنوان دروازه سازگاری ثانویه اجرا می‌شود. هر دو موتور یک Harness
مشترک را اجرا می‌کنند: ساخت Schema خالی، اجرای Migration دوباره، بازسازی یک Fixture
قدیمی، اجرای دوباره Migration بدون تغییر ردیف‌های Seed، کنترل Table/Index/FK و اجرای
دو‌باره Backfill دفتر امتیاز همراه Reconciliation.

`AUTO_MIGRATE=false` پیش‌فرض است. استقرار ابتدا Backup می‌گیرد و سپس Migration را
به‌صورت کنترل‌شده اجرا می‌کند؛ شروع خودکار برنامه نباید Schema را تغییر دهد.

گردش‌کار Android روی Pull Request و Push شاخه‌های `main` و `codex/**` اجرا می‌شود.
APK تولیدی فقط Debug کوتاه‌عمر و بدون امضای Release است. آدرس Backend در BuildConfig
تزریق می‌شود و شبیه‌سازهای API 23، 29 و 35 فقط به Backend موقت CI روی
`10.0.2.2:3000` متصل می‌شوند. مجوز HTTP فقط در Resource مربوط به Debug فعال است؛
Release همچنان HTTPS را الزام می‌کند. انتشار و امضای پایدار APK تصمیم و فرایندی جدا
و نیازمند مجوز صریح و نگهداری امن کلید امضا است.
