# اپ Android کارمند تپرا

این پوشه نسخه Android سامانه را می‌سازد. رابط کاربری از دامنه امن
`https://taprasystem.ir` بارگذاری می‌شود و ثبت موقعیت در زمان فعالیت توسط سرویس
بومی Android ادامه پیدا می‌کند؛ حتی وقتی نمایشگر خاموش یا اپ از صفحه خارج شده است.

## سازگاری

- حداقل نصب Android 6.0 (API 23)؛ اجرای سایت نیازمند WebView و گواهی‌های سیستمِ به‌روز است.
- هدف Android 15 (API 35)
- معماری مستقل از پردازنده؛ APK روی ARM و x86 نصب می‌شود.

نمایشگرهای پیش‌فرض قدیمی API23/29 در آزمایش قادر به اجرای سایت نبودند. نسخه
۱.۲.۴ برای WebView ناشناخته یا Chrome کمتر از ۸۰، پیام بومی به‌روزرسانی رسمی
نشان می‌دهد؛ این حد پایین، تضمین سازگاری همه نسخه‌های بالاتر نیست. خطای گواهی
SSL همچنان اتصال را متوقف می‌کند. تست API35 باید ورود واقعی را اثبات کند؛
تست شبیه‌سازهای قدیمی فقط رد صحیح نمایشگر ناسازگار را می‌سنجد.

## ساخت نسخه آزمایشی

از داخل پوشه `android`:

```text
gradle --no-daemon lintDebug testDebugUnitTest assembleDebug
```

خروجی در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد. نسخه ۱.۲.۰ در صورت
برخی خطاهای بارگذاری، کش قدیمی یا قطع اینترنت پیام خطا و امکان تلاش مجدد دارد؛
این به معنی تضمین اجرا روی هر WebView یا نبود همه علت‌های صفحه سفید نیست.

آدرس Backend در BuildConfig قرار دارد. نسخه Release فقط از
`https://taprasystem.ir` استفاده می‌کند و تنظیم آدرس دیگری برای آن باعث شکست ساخت می‌شود. برای تست محلی شبیه‌ساز می‌توان Debug را با
`-PtapraDebugBackendUrl=http://10.0.2.2:3000` ساخت؛ مجوز cleartext فقط در منبع Debug
فعال است و وارد Release نمی‌شود. APK گردش‌کار CI یک خروجی Debug آزمایشی است، نه
نسخه قابل انتشار. امضای پایدار Release باید در فرایند جداگانه و با کلید امن انجام شود.

این checkout فاقد Gradle Wrapper است؛ ساخت به JDK 17، Gradle 8.11.1 و Android SDK 35
نیاز دارد (همان محیط CI). نسخه آماده ساخت ۱.۲.۴ با versionCode برابر ۲۳ است.
پسوند ۲۲ در Release قبلی `android-test-v1.2.3-22` شماره اجرای گردش‌کار بوده، نه
دلیل قطعی برای versionCode داخل APK. APK آزمایشی CI به Backend محلی شبیه‌ساز
وصل است و نباید برای کارمند فرستاده شود.

## امضای ثابت و انتشار ۱.۲.۴

نسخه قبلی با کلید موقت Debug ساخته شده و کلید سازگار آن در محل‌های بررسی‌شده
یافت نشده است. کاربر تعویض یک‌باره با همان package ID را تأیید کرده است؛ این
نسخه، ارتقای درجا روی امضای قبلی نیست. حذف/پاک‌کردن خودکار برنامه یا صف ممنوع است.
پیش از حذف دستی، خالی‌بودن **هر دو صف وب و GPS بومی پس از پایان فعالیت** باید
قابل اثبات باشد؛ شمارنده وب به‌تنهایی کافی نیست.

- `scripts/android/Initialize-TapraSigning.ps1` فقط با اقدام صریح، کلید ثابت خارج
  از Git ایجاد می‌کند؛ مسیر موجود هرگز جایگزین نمی‌شود. رمز در Windows CurrentUser
  DPAPI و فایل‌ها با ACL محدود نگه‌داری می‌شوند. پشتیبان محلی با نسخه اصلی تطبیق
  داده می‌شود؛ بازیابی مستقل از ویندوز/حساب فعلی هنوز به پشتیبان امن جدا نیاز دارد.
- ساخت Release از `lintRelease testReleaseUnitTest assembleRelease` استفاده می‌کند.
  خروجی خودکار CI می‌تواند APK **بدون امضا** برای امضای محلی بدهد؛ فایل کلید یا
  رمز وارد CI نمی‌شود. `testReleaseUnitTest` ممکن است `NO-SOURCE` باشد؛ تست‌های
  Java مستقل و آزمون شبیه‌ساز باید جداگانه گزارش شوند.
- `scripts/android/Sign-TapraRelease.ps1` از کلید موجود استفاده می‌کند، قبل از
  امضا alignment را انجام می‌دهد و گواهی نهایی را با هویت ثابت تطبیق می‌دهد.
- آزمون دستی CI فایل نهایی امضاشده را از asset همان مخزن یا Payload عمومی کوچک
  با SHA-256 صریح و تأییدشده می‌گیرد؛ هیچ کلید امضایی منتقل نمی‌شود.
  نصب و جایگزینی با **همان کلید جدید** را روی شبیه‌سازهای تازه بررسی می‌کند. هیچ
  حساب واقعی وارد نمی‌شود و هیچ مأموریت/فعالیت واقعی ایجاد نمی‌شود.

## مجوزهای لازم روی گوشی

در اولین اجرا، Location دقیق و اعلان‌ها را مجاز کنید. هنگام فعالیت، اعلان دائمی
«ثبت موقعیت فعالیت در حال اجراست» نمایش داده می‌شود. حذف این اعلان یا Force Stop
کردن برنامه می‌تواند ثبت پس‌زمینه را متوقف کند.
